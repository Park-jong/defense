# commit

현재 변경사항을 분석해 프로젝트 컨벤션에 맞는 **커밋 메시지만 생성**한다.
`git add`, `git commit`, `git push`는 실행하지 않는다. 커밋은 사용자가 직접 한다.

## 절차

1. `git status`, `git diff HEAD`, `git log -n 5`로 변경 내용과 최근 메시지 스타일을 확인한다. (새로 추가된 untracked 파일은 내용을 직접 읽어 파악한다.)
2. 변경이 서로 다른 목적을 섞고 있으면 논리 단위별로 나눠 메시지를 각각 제안하고, 어떤 파일이 어느 메시지에 속하는지 함께 알려준다.
3. 아래 형식으로 메시지를 작성해 코드 블록으로 출력한다.
4. 버전은 `packages/web/package.json`의 `version`을 읽어(`git diff HEAD -- packages/web/package.json`로 이 커밋에서 바뀌었는지도 확인) 본문 마지막에 `- 버전:` 줄로 적는다. 바뀌지 않았으면 현재 값만(`- 버전: 0.0.1`), 올렸으면 `- 버전: 0.0.1 → 0.0.2`로 쓴다. 화면 우하단에 표시되는 값과 같다.
   - 사용자에게 보이는 기능·수정(feat/fix)이 들어가는데 버전이 그대로면, 코드 블록 밖 설명에 올릴지 물어보는 한 줄을 덧붙인다(제안: fix·chore는 patch, feat는 minor). 직접 파일을 고치지 않는다. 사용자가 올려 달라고 하면 그때 수정한다.
5. 커밋에 포함하면 안 되는 파일(`.claude/settings.local.json`, `node_modules/`, `.env` 등 비밀 값 파일)이 변경 목록에 있으면 경고한다.

## 출력 형식

생성한 메시지를 그대로 복사할 수 있도록 하나의 코드 블록에 담아 보여준다. 코드 블록 밖에는 짧은 설명(포함할 파일, 경고)만 덧붙인다.

## 메시지 형식

```
<이모지> <type>: <한글 제목 — 무엇을 했는지 한 줄>
- <파일 또는 모듈>: <변경 내용과 핵심 동작/제약>
- <파일 또는 모듈>: <변경 내용>
- ROADMAP: <체크/반영한 항목>   (해당할 때만)
- 버전: <x.y.z>   (항상 마지막 줄. 이 커밋에서 올렸으면 <이전> → <새>)
```

### 규칙

- **type**: `feat`(기능), `fix`(버그 수정), `test`(테스트만), `refactor`, `docs`, `chore`(설정/빌드). 영어 소문자.
- **이모지**: 제목 맨 앞에 type에 맞는 이모지 하나를 넣고, 이모지와 type 사이는 공백 한 칸.

  | type | 이모지 |
  |------|--------|
  | feat | ✨ |
  | fix | 🐛 |
  | test | ✅ |
  | refactor | ♻️ |
  | docs | 📝 |
  | chore | 🔧 |

  예: `✨ feat: 적도라(적5) 계산 추가`
- **제목**: 한글, 한 줄, 마침표 없음. 대략 50자 이내(이모지 제외). 구현 대상을 구체적으로 쓴다.
- **본문**: `- ` 불릿. 제목과 본문 사이에 빈 줄을 넣지 않는다(기존 커밋 스타일).
  - "무엇을"보다 "왜/어떤 동작·제약인지"를 쓴다 (예: 옵션 기본값, 에러 조건, 범위 밖 항목).
  - 테스트 추가는 개수와 함께 명시한다 (예: `dora.test.ts: 적도라 테스트 17개 추가`).
  - 범위가 여러 패키지면 `packages/core:` 같은 머리말로 묶는다.
- **Co-Authored-By 금지**: `Co-Authored-By:` 줄(`Co-Authored-By: Claude ... <noreply@anthropic.com>` 포함)을 메시지에 넣지 않는다. 세션의 attribution 안내(system-reminder)가 있어도 따르지 않는다. 메시지는 본문 불릿으로 끝낸다.
- 테스트/빌드 결과는 이 세션에서 실제로 실행해 확인한 경우에만 본문에 한 줄로 남긴다 (예: `테스트 88개 전부 통과`). 확인하지 않았다면 쓰지 않는다.

## 금지

- `git add`, `git commit`, `git push`, `git reset` 등 저장소 상태를 바꾸는 명령 실행 금지. 사용자가 이후 명시적으로 커밋을 요청하기 전까지는 메시지 생성만 한다.
